## What This Is

`react-native-nitro-cardinal-direction` is a React Native [Nitro Module](https://nitro.margelo.com) that provides real-time magnetic compass heading via `startUpdates` / `stopUpdates`. It uses the device accelerometer + magnetometer on Android (NDK sensor API) and CoreMotion on iOS. No runtime permissions are required.

## Commands

```bash
# Type-check TypeScript
npm run typecheck

# Compile TypeScript → lib/
npm run typescript    # or: npm run prepare

# Regenerate Nitrogen specs (run after editing src/specs/*.nitro.ts)
npm run specs

# Lint (auto-fix)
npm run lint

# Clean build artefacts
npm run clean
```

There are no tests in this project.

## Architecture

### Spec-first Nitro workflow

1. **TypeScript spec** (`src/specs/CardinalDirection.nitro.ts`) — defines the public API as a `HybridObject` interface. This is the single source of truth.
2. **`npm run specs`** — runs `tsc` then `nitrogen`, which reads `nitro.json` and auto-generates C++ abstract base classes (`nitrogen/generated/shared/c++/HybridCardinalDirectionSpec.hpp`) plus platform autolinking glue (iOS `.rb`/`.mm`/`.swift`, Android `.cmake`/`.gradle`/`.cpp`).
3. **Hand-written implementations** extend the generated spec:
   - `cpp/HybridCardinalDirection.hpp` / `.cpp` — Android NDK implementation (accelerometer + magnetometer, sensor loop on a detached thread)
   - `ios/HybridCardinalDirection.mm` — iOS implementation (CoreMotion `CMMotionManager`, runs on an `NSOperationQueue`)

### Key implementation details

- **Android heading** is computed manually from raw accelerometer + magnetometer vectors via a rotation-matrix / cross-product approach (`calculateAzimuth`). Display rotation is fetched at runtime from the Java `OrientationHelper` class via JNI so that heading is always portrait-relative regardless of device orientation.
- **iOS heading** uses `CMAttitudeReferenceFrameXMagneticNorthZVertical`; the `yaw` value is negated and converted to a 0–360 bearing, then corrected for `UIDeviceOrientation`.
- Both platforms apply a **1-degree noise gate** (`HEADING_THRESHOLD`) to suppress callbacks for sub-degree jitter.
- Sensor polling rate is 100 ms on both platforms.

### Directory layout (non-obvious parts)

| Path | Purpose |
|---|---|
| `src/specs/` | Nitro TypeScript spec (edit here to change the API) |
| `cpp/` | Shared header + Android-only `.cpp` implementation |
| `ios/` | Objective-C++ iOS implementation (`.mm`) |
| `nitrogen/generated/` | **Do not edit** — fully regenerated by `npm run specs` |
| `lib/` | Compiled JS/d.ts output — do not edit, rebuilt by `npm run typescript` |
| `nitro.json` | Nitrogen config: namespace, module name, autolinking settings |

### Changing the API

1. Edit `src/specs/CardinalDirection.nitro.ts`.
2. Run `npm run specs` to regenerate the C++ spec header.
3. Update `cpp/HybridCardinalDirection.hpp` and the platform implementations to match.
